## 资料分析笔记：比值型公式（真分数）写入

- 背景：11-18 晚想插入「比值型公式 + 整体比值规则」并把 ÷ 改成上下结构分式，但 docx 一直被 WPS 占用（`~$资料分析笔记.docx` 锁 + 写入 Permission denied），编辑器实例内改动最终随预览实例关闭丢失，磁盘仍是 11-18 11:27 版本。
- 解决：用户关闭 WPS 后确认「可读、可改名、r+b 可写」三态再动手；**不依赖 editor_sdk**，改用 python-docx + lxml 直接构造 OMML 写入并保存（一次成功，无占用问题）。
- 插入位置：`7. 混合增速`（Heading 3）之后、`8. 隔年增长 ★` 之前，共 4 段：
  1. 加粗小标题「比值型公式（结构统一：分子 / 分母）」
  2. 浓度 = 溶质质量/溶液质量　增长率 = 增长量/基期值（m:f 真分式）
  3. 平均数 = 总量/份数　比重 = 部分值/整体值
  4. 「整体比值规则（通用）：整体比值介于部分比值之间，且靠近**分母较大**的部分（分母＝权重）……」
- 技术要点（可复用）：
  - OMML 分式最小结构：`m:oMath > m:f > (m:fPr, m:num, m:den)`，分子/分母为 `m:r`，内含 `m:rPr(m:sty val=p)` + `w:rPr(rFonts=Cambria Math, sz=21, szCs=21)` + `m:t`。`sty=p` 让中文不带斜体。
  - 用 `etree.SubElement(父节点, '{math命名空间}oMath')` 直接建节点，序列化会自动复用文档根节点的 m 前缀，不必手写 xmlns。
  - 含分式的段落行距设为 `lineRule="atLeast" line=440`，避免 Word/WPS 按固定倍数行距裁切分式。
  - 正文 run 统一 微软雅黑 + sz=21（10.5pt），与全文一致。
- 结果校验：段落 74→78、表格 7 不变、公式 84→88、zip 完整、48.3 KB。备份在 `_临时文件/资料分析笔记-备份-20261119.docx`，脚本 `_临时文件/insert_ratio_formulas.py`。
- 教训：**editor_sdk 只在实例存活期间持有改动**，实例一关内存改动就没了；文件被 Office/WPS 占用时应先确认锁解除，再选「直接写盘」而非「编辑器内存等保存」。

## git push 代理修复（第二次）

- 症状：`Failed to connect to github.com port 443 via 127.0.0.1 after 2052 ms`——11-09 给仓库设的 `http.proxy=127.0.0.1:63147`（当次 WorkBuddy 会话的临时代理端口）已失效。
- 关键发现：**Windows 系统代理是固定端口 `127.0.0.1:7897`**（注册表 HKCU\...\Internet Settings，ProxyEnable=1），而 WorkBuddy 会话内的 `http_proxy` 环境变量是每次会话变化的临时端口（这次是 54396）。git for Windows **既不读注册表也不自动读会话代理**，必须显式配。
- 处理：仓库级 `git config http.proxy/https.proxy = http://127.0.0.1:7897`（固定端口，不随会话失效），push 成功 `c847056..8a33a96`，4 个提交。
- 以后 push 报 `via 127.0.0.1` 连不上时，先 `curl -sI -x http://127.0.0.1:7897 https://github.com` 验证代理，再改配置；**优先用 7897，不要用会话临时端口**。
- 后续：用户要求「取消代理」→ 已 `git config --unset http.proxy/https.proxy`（仓库级），全局本就没有。清空代理环境变量后实测 **直连 GitHub 可用**（`git ls-remote`、`git push` 均 exit 0），当前网络无需代理即可推送。若日后直连失败，再补 `7897`。
